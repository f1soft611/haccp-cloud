# 플랫폼 관리자 대시보드 상단(로그인 정보 영역) 디자인 개선 설계서

- 작성일: 2026-06-19
- 범위: 플랫폼 관리자 대시보드 상단 UI
- 목적: 로그인 메인화면 상단을 요구사항에 맞게 재구성하고, 추후 확장 가능한 구조로 정리한다.

## 1. 배경

현재 플랫폼 관리자 대시보드 상단은 제목, 빠른 액션, 로그인 정보 카드 중심의 최소 구조다. 요청된 레퍼런스 화면 기준으로 다음 요구가 추가되었다.

1. 타이틀 제거
2. 좌측 영역은 자주 찾는 메뉴를 권한별 기본값으로 표시
3. 우측 로그인 정보 영역은 아이디 대신 사용자명과 권한 표시
4. 비밀번호 변경 기능은 별도 페이지 이동 방식
5. 레퍼런스 이미지의 검색란은 제거

또한 추후 좌측 메뉴의 추가/제거 기능 확장을 고려해, 이번 변경은 상단을 별도 컴포넌트로 분리하는 확장 우선안으로 진행한다.

## 2. 목표

1. 플랫폼 관리자 대시보드 상단 타이틀을 제거한다.
2. 상단을 좌측/우측 2컬럼 영역으로 재구성한다.
3. 좌측에 권한 기반 기본 자주 찾는 메뉴를 표시한다.
4. 우측 로그인 정보 카드에서 아이디를 완전 비노출 처리한다.
5. 우측 카드에 비밀번호 변경 버튼을 추가하고 별도 페이지로 이동시킨다.
6. 상단 검색 입력 UI를 제거한다.
7. 모바일에서 자연스럽게 세로 배치로 반응형 동작한다.

## 3. 비목표

1. 좌측 자주 찾는 메뉴 편집 UI(추가/삭제/정렬) 구현
2. 비밀번호 변경 API 연동의 최종 완료
3. 테넌트 관리자/일반 사용자 대시보드 상단 레이아웃 통합 변경
4. 하단 KPI/테이블 섹션의 정보 구조 변경

## 4. 설계 개요

선택한 접근은 상단 전용 컴포넌트 분리 + 라우트 확장 방식이다.

1. 상단 UI를 별도 컴포넌트로 분리한다.
2. 좌측 자주 찾는 메뉴는 권한별 기본 목록 상수로 관리한다.
3. 우측 로그인 정보는 사용자명, 권한만 표시한다.
4. 비밀번호 변경 버튼은 신규 경로(`/account/password`)로 이동한다.
5. 기존 로그아웃 동작은 유지한다.

## 5. 화면 구조 설계

### 5.1 상단 컨테이너

- 기존 제목 텍스트를 제거한다.
- 상단 첫 블록은 2컬럼으로 구성한다.
  - 좌측: 자주 찾는 메뉴 카드
  - 우측: 로그인 정보 카드
- 반응형 기준
  - 데스크톱: 2컬럼(좌 8, 우 4 또는 유사 비율)
  - 모바일: 세로 스택

### 5.2 좌측 자주 찾는 메뉴 카드

- 카드 제목: 자주 찾는 메뉴
- 본문: 권한별 기본 메뉴 칩/버튼 목록
- 데이터 소스: 권한별 기본 메뉴 정의 상수
- 각 메뉴는 내부 라우트 링크를 가진다.

권한별 초기 기본 메뉴 예시:

1. PLATFORM_ADMIN
   - 대시보드
   - 메뉴관리
   - 권한/메뉴관리
   - 로그인 이력
2. TENANT_ADMIN
   - 대시보드
   - 사용자관리
   - 부서관리
   - 문서관리
3. TENANT_USER
   - 대시보드
   - 문서관리
   - 문서이력

확장 고려 사항:

- 메뉴 아이템 타입에 `enabled` 플래그를 포함해 추후 사용자 맞춤 편집을 수용한다.
- 추후 서버 API 기반 즐겨찾기/최근 메뉴로 교체 가능하도록 인터페이스를 분리한다.

### 5.3 우측 로그인 정보 카드

- 표시 항목
  - 사용자명
  - 권한명
- 미표시 항목
  - 아이디(userId) 완전 미노출
- 액션
  - 비밀번호 변경: 신규 페이지로 이동
  - 로그아웃: 기존 동작 유지

사용자명 데이터 정책:

- `authStore`에 사용자명 필드가 없거나 비어 있으면 임시로 `userId`를 사용자명처럼 그대로 노출하지 않는다.
- fallback 라벨은 `사용자`로 고정해 아이디 노출 요구와 충돌하지 않게 한다.
- 이후 인증 응답에 사용자명(displayName)이 추가되면 그대로 연결한다.

## 6. 라우팅 및 페이지 설계

### 6.1 신규 라우트

- 경로: `/account/password`
- 접근 조건: 로그인 사용자 전체 허용(ProtectedRoute 내부)
- 위치: 기존 라우트 정의 파일에 추가

### 6.2 비밀번호 변경 페이지

초기 버전 구성:

1. 페이지 타이틀: 비밀번호 변경
2. 폼 필드
   - 현재 비밀번호
   - 새 비밀번호
   - 새 비밀번호 확인
3. 액션 버튼
   - 저장
   - 취소(대시보드 복귀)

확장성 고려:

- 안내 패널, 비밀번호 정책 설명, 보안 알림 영역을 추후 붙일 수 있도록 상/중/하 블록 구조로 작성한다.

## 7. 컴포넌트 경계

### 7.1 신규/분리 컴포넌트

- `PlatformAdminDashboardTopSection` (신규)
  - 상단 2컬럼 전체 조합
- `QuickMenuCard` (신규)
  - 권한별 메뉴 목록 표시
- `LoginInfoCard` (신규)
  - 사용자명/권한/비밀번호변경/로그아웃 표시

### 7.2 기존 컴포넌트 변경

- `PlatformAdminPanels`
  - 기존 상단 헤더 영역 제거
  - 신규 상단 컴포넌트 렌더링으로 대체

## 8. 데이터 흐름

1. 대시보드 진입
2. `authStore`에서 `role`, `displayName`(없으면 fallback), 로그아웃 액션 참조
3. `role` 기반으로 기본 quick menu 목록 결정
4. 메뉴 클릭 시 해당 라우트로 이동
5. 비밀번호 변경 클릭 시 `/account/password` 이동
6. 로그아웃 클릭 시 기존 API 호출 후 로컬 인증 상태 초기화

## 9. 오류 처리

1. 사용자명 부재
   - 아이디를 대체 노출하지 않고 `사용자` 고정 텍스트 표시
2. 권한 라벨 매핑 실패
   - 기존 `getRoleLabel` 기본 분기 사용
3. 비밀번호 변경 페이지 진입 후 API 미연동 상태
   - 폼 제출 시 안내 메시지 또는 mock 처리로 안전하게 실패 알림

## 10. 테스트 전략

### 10.1 단위/컴포넌트 테스트

1. 플랫폼 관리자 상단에서 타이틀이 렌더링되지 않는다.
2. 로그인 정보 카드에 userId 문자열이 렌더링되지 않는다.
3. 사용자명/권한은 렌더링된다.
4. 비밀번호 변경 버튼 클릭 시 `/account/password`로 이동한다.
5. 좌측 자주 찾는 메뉴가 권한별 기본 목록대로 렌더링된다.
6. 상단 검색 입력 관련 요소가 렌더링되지 않는다.

### 10.2 라우팅 테스트

1. 로그인 상태에서 `/account/password` 접근 가능
2. 비로그인 상태에서 `/account/password` 접근 시 `/login` 리다이렉트

### 10.3 회귀 테스트

1. 기존 플랫폼 관리자 KPI/섹션 렌더링은 유지
2. 로그아웃 버튼 동작 유지
3. 테넌트/일반 사용자 대시보드 렌더링 영향 없음

## 11. 구현 순서

1. 상단 분리 컴포넌트(TopSection, QuickMenuCard, LoginInfoCard) 추가
2. `PlatformAdminPanels` 상단 헤더를 신규 컴포넌트로 교체
3. 신규 비밀번호 변경 페이지 추가
4. `AppRoutes`에 `/account/password` 라우트 추가
5. 라벨 상수 및 테스트 텍스트 정리
6. 관련 테스트 추가/수정 및 검증

## 12. 수용 기준

1. 플랫폼 관리자 상단 타이틀이 제거된다.
2. 좌측에 권한별 자주 찾는 메뉴가 기본 노출된다.
3. 우측 로그인 카드에는 사용자명/권한만 표시되고 아이디는 보이지 않는다.
4. 비밀번호 변경 버튼 클릭 시 별도 페이지로 이동한다.
5. 상단 검색란은 렌더링되지 않는다.
6. 기존 플랫폼 관리자 대시보드 핵심 기능(KPI/섹션/로그아웃)은 유지된다.
