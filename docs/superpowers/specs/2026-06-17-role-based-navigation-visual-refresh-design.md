# Role-Based Navigation Visual Refresh Design

## 1. Goal

메뉴를 단순 링크 모음이 아닌 역할 기반 네비게이션 허브로 재정의한다.
상단 1차 그룹 네비와 하단 2차 기능 메뉴를 분리해 탐색 구조를 명확히 하고,
권한별 노출 정책을 일관되게 적용해 지저분한 시각 노이즈와 사용자 혼란을 줄인다.

## 2. Confirmed Decisions

- 전체 톤은 공공/엔터프라이즈 미니멀로 확정한다.
- 메뉴 밀도는 균형형(현재 대비 약 15~20% 컴팩트)으로 조정한다.
- 상단 그룹 네비는 세그먼트 버튼 형태를 사용한다.
- 메뉴는 네비게이션 역할이 핵심이며, 권한별 노출 정책을 UI와 라우트에서 동시 적용한다.

## 3. Information Architecture

### 3.1 Two-Level Navigation

- 1차 네비: 상단 그룹 세그먼트(예: 대시보드 관리, 시스템 관리)
- 2차 네비: 선택 그룹에 속한 기능 메뉴 패널
- 현재 위치는 1차 active + 2차 active를 동시에 유지한다.

### 3.2 Permission-Based Visibility

- 사용자 권한으로 2차 메뉴를 필터링한다.
- 필터 후 하위 메뉴가 0개인 그룹은 1차 그룹에서도 숨긴다.
- 로그인 직후 접근 가능한 첫 메뉴로 자동 진입한다.

### 3.3 Direct URL and Guard Consistency

- UI 숨김 여부와 관계없이 직접 URL 접근은 라우트 가드에서 다시 검증한다.
- 권한 키는 메뉴 구성, 라우트 가드, API 인가 정책에서 동일 식별자를 사용한다.

## 4. Interaction and State Rules

- 기본 정책은 숨김 우선이며, 비권한 메뉴를 비활성 상태로 노출하지 않는다.
- 예외적으로 권한 요청이 필요한 화면만 안내 문구와 문의 동선을 제공한다.
- 메뉴 로딩 중에는 스켈레톤으로 레이아웃 점프를 최소화한다.
- 메뉴 API 실패 시 섹션 단위 오류 메시지와 재시도 버튼을 제공한다.
- 권한 갱신 시 메뉴 계산을 재수행하고 active 상태를 유효 경로로 보정한다.

## 5. Visual Design System

### 5.1 Primary Group Segments

- 상단 그룹은 연한 배경 + 1px 외곽선 컨테이너 위에 배치한다.
- active 그룹만 브랜드 톤 배경/텍스트를 적용하고, 비활성은 중립 텍스트 톤을 사용한다.
- 기존 언더라인 중심 강조를 줄이고 세그먼트 내부 대비로 상태를 구분한다.

### 5.2 Secondary Menu Panel

- 카드 구조는 아이콘, 제목, 설명의 3단 위계로 고정한다.
- 카드 높이는 균형형 밀도로 조정해 스캔성을 높인다.
- 과한 세로 경계선 대신 여백과 배경 대비로 카드 경계를 인지시킨다.
- hover는 미세한 배경 변화 중심으로 통일하고 과도한 이동 애니메이션은 배제한다.

### 5.3 Overlay and Layering

- 딤 레이어 투명도를 낮춰 콘텐츠 가독성을 우선한다.
- 블러 효과는 제거하거나 최소값으로 제한한다.
- 패널 그림자는 단일 소프트 섀도우를 사용하고 중첩 섀도우를 금지한다.

## 6. Responsive and Accessibility

- 모바일에서는 1차 세그먼트 가로 스크롤을 허용한다.
- 모바일 2차 메뉴는 1열 카드로 전환해 탭 오차를 줄인다.
- 키보드 탐색(Tab, Enter, Space)과 명확한 focus ring을 보장한다.
- 텍스트 대비는 WCAG AA 이상을 목표로 설정한다.

## 7. Component-Level Change Targets

- frontend/src/shared/components/layout/WorkMenuBar.tsx
  - 상단 그룹을 세그먼트 형태로 재구성
  - 2차 메뉴 카드 밀도/경계/상태 표현 단순화
  - 권한 필터 후 빈 그룹 숨김 규칙을 명시적으로 반영
- frontend/src/shared/components/layout/PageHeader.tsx
  - 상단 메뉴 밀도 조정에 맞춰 제목/보조텍스트 위계 재정렬
- frontend/src/app/theme.ts
  - 네비게이션용 중립/강조 토큰을 추가해 색/경계/그림자 일관성 확보

## 8. Error and Fallback Behavior

- 권한 기반 필터 결과가 전체 빈 상태일 경우 안내 문구와 문의 액션을 제공한다.
- 현재 active 경로가 권한 변경으로 무효가 되면 접근 가능한 첫 경로로 안전 이동한다.
- 메뉴 데이터 응답 지연 시 마지막 유효 메뉴 스냅샷을 유지해 깜빡임을 줄인다.

## 9. Testing Strategy

- 단위/컴포넌트 테스트
  - 권한별 그룹/메뉴 노출 규칙 검증
  - 빈 그룹 자동 숨김 검증
  - active 상태 유지 및 라우트 이동 검증
- 접근성 테스트
  - 키보드 조작 및 focus 표시 검증
  - 대비 기준 주요 상태(active, hover, disabled) 검증
- 회귀 테스트
  - 기존 역할별 라우트 접근 정책 유지 검증
  - 메뉴 API 실패 시 오류/재시도 동작 검증

## 10. Scope

### Included

- 2단 네비(그룹 세그먼트 + 권한 메뉴 패널) UX 정리
- 권한별 메뉴 노출/숨김 규칙 강화
- 상단 메뉴 비주얼 리프레시(미니멀 톤)
- 반응형/접근성 기준 반영
- 관련 테스트 갱신

### Excluded

- 권한 모델 자체 변경(새 역할 추가)
- 신규 백엔드 권한 체계 도입
- 대시보드 본문 카드 구조 전면 개편

## 11. Risks and Mitigations

- Risk: 숨김 우선 정책으로 기능 발견성이 낮아질 수 있음
  - Mitigation: 필요한 화면에만 권한 요청 동선을 제공하고 관리자 가이드를 문서화
- Risk: 권한 계산과 라우트 가드 불일치
  - Mitigation: 동일 권한 키를 공유하고 테스트에서 UI/라우트 동시 검증
- Risk: 스타일 단순화 후 구분감 저하
  - Mitigation: 대비는 색이 아니라 위계(크기, 굵기, 여백)와 active 상태로 보완
