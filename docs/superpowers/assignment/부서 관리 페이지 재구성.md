# [작업지시서] 부서 관리 페이지 재구성

## 1. 배경 및 목표

현재 `DepartmentsPage.tsx`는 단순 텍스트 입력 + 플랫 테이블 구조로 구현되어 있으며,  
부모/자식 계층 관계 표현, 수정/삭제, 검색 기능이 모두 누락된 상태이다.

**목표**: 메뉴 관리 페이지(`/platform/menus`)와 동일한 UI/구조/개발 패턴으로 전면 재구성한다.

## 4. 작업 내용

### 4-1. Frontend

#### 타입 확장 (`departmentsService.ts`)

```typescript
export type DepartmentItem = {
  id: string;
  tenantCode: string;
  name: string;
  parentId: string | null;
  parentName: string | null;
  sortOrder: number;
  active: boolean;
  hasChildren: boolean;
  // 트리 렌더링용 (프론트 파생 필드)
  depth?: number;
  children?: DepartmentItem[];
};

export type DepartmentSearchParams = {
  tenantCode: string;
  name?: string;
  active?: 'Y' | 'N' | '';
};
```

#### 서비스 추가/수정 (`departmentsService.ts`)

- `listDepartments(params: DepartmentSearchParams)` — 검색 파라미터 지원
- `createDepartment({ tenantCode, name, parentId, sortOrder })` — parentId, sortOrder 추가
- `updateDepartment({ id, name, parentId, sortOrder, active })` — 신규 구현
- `deleteDepartment({ tenantCode, id })` — 신규 구현

#### 컴포넌트 재구성

```
DepartmentsPage.tsx                ← 페이지 진입점 (검색 상태, 모달 제어)
└─ components/
   ├─ DepartmentSearchBar.tsx      ← 검색 조건 폼 (메뉴 관리 SearchBar 패턴)
   ├─ DepartmentTreeGrid.tsx       ← Tree Grid (expand/collapse, 행 렌더링)
   ├─ DepartmentRow.tsx            ← 단일 행 컴포넌트 (depth indent 처리)
   └─ DepartmentFormModal.tsx      ← 등록/수정 공통 모달
      └─ 필드: 부서명(필수), 상위 부서 선택, 순서, 사용여부
```

#### 기존 `DepartmentGrid.tsx` 처리

- `DepartmentTreeGrid.tsx`로 완전 교체 → 기존 파일 제거

### 4-2. Backend

#### API 추가/수정 대상

| Method | Endpoint            | 설명                                              | 현재        |
| ------ | ------------------- | ------------------------------------------------- | ----------- |
| GET    | `/departments`      | 검색 파라미터(name, active) 지원 + 계층 포함 반환 | ⚠ 수정 필요 |
| POST   | `/departments`      | parentId, sortOrder 포함                          | ⚠ 수정 필요 |
| PUT    | `/departments/{id}` | 전체 수정                                         | ❌ 미구현   |
| DELETE | `/departments/{id}` | 자식 부서 없을 때만 삭제                          | ❌ 미구현   |

#### VO/DTO 수정 대상

- 부서 엔티티에 `parent_dept_id`, `sort_order` 컬럼 확인 (없으면 마이그레이션)
- 응답 VO에 `parentName`, `hasChildren`, `depth` 파생 필드 포함

#### 비즈니스 규칙

- 자식 부서가 존재하면 삭제 차단 (409 응답)
- 자기 자신 또는 자손을 상위 부서로 설정 불가 (순환 참조 방지)
- 삭제 전 해당 부서에 배정된 사용자 존재 시 경고 또는 차단 (정책 확인 필요)
