공통 작업지시서 팀 표준 템플릿 (간단 버전)

프론트엔드/백엔드 개발 패턴 준수를 위한 최소 양식

사용 목적

작업지시서를 빠르게 작성하되, 프론트엔드/백엔드 개발 패턴은 반드시 지키기 위한 최소 양식이다.

작성 템플릿

아래 블록을 복사해서 사용한다.

# [작업지시서] {작업 제목}

- 배경:
- 목표:

## 2) 해야 할 일
- 필수 요구사항:
1.
2.

## 3) 영향 범위
- 프론트엔드: 있음/없음 (내용)
- 백엔드: 있음/없음 (내용)
- DB: 있음/없음 (내용)

## 4) 패턴 준수 체크
### 프론트엔드
- [ ] API 호출은 services 계층에서만 처리
- [ ] UI 컴포넌트는 표현 중심, 비즈니스 로직은 분리
- [ ] 공통 타입/응답 모델 기준으로 구현

### 백엔드
- [ ] Controller-Service-DAO 책임 분리
- [ ] 예외/응답 포맷 규칙 준수
- [ ] SQL/매퍼/스키마 변경 시 문서 동기화

## 5) 테스트
- [ ] 핵심 시나리오 테스트 통과
- [ ] 변경 영향 영역 회귀 확인

## 6) 완료 조건 (DoD)
- [ ] 요구사항 충족
- [ ] 패턴 준수 체크 완료
- [ ] 테스트 통과
- [ ] 리뷰 완료

## 7) 담당
- 담당자:
- 리뷰어:
- 목표 완료일:

운영 규칙

  1. 작업 시작 전 5분 안에 템플릿을 작성한다.
  2. 개발 중 변경사항이 생기면 2) 해야 할 일과 3) 영향 범위를 즉시 갱신한다.
  3. 완료 보고 시 4) 패턴 준수 체크와 5) 테스트를 함께 제출한다.
