협업을 위한 개발 가이드 (교육안)

일시: 2026-06-30

대상: 프론트엔드/백엔드 개발자

목적: 팀 내 개발 방식 통일과 AI 기반 협업 생산성 향상

1. 프로젝트 구조 간단 설명 (프론트, 백엔드)

프론트엔드

  • 위치: frontend/
  • 핵심 구조
    • src/app: 앱 공통 초기화 및 라우팅/전역 설정
    • src/pages: 화면 단위 기능
    • src/services: API 통신 및 비즈니스 로직 연계
    • src/shared: 공통 컴포넌트, 유틸, 타입
    • src/test: 테스트 코드
  • 개발 포인트
    • 기능별 폴더 구조를 유지하고 공통 로직은 shared로 분리
    • API 경로/응답 스키마를 서비스 계층에서 일관되게 관리

백엔드

  • 위치: backend/
  • 핵심 구조
    • src/main/java: 도메인/서비스/컨트롤러 구현
    • src/main/resources: 설정 및 매퍼/리소스
    • src/test/java: 단위/통합 테스트
    • DATABASE: 스키마, 마이그레이션, 시드, 운영 스크립트
  • 개발 포인트
    • 계층 분리(Controller-Service-DAO) 준수
    • SQL/매퍼 변경 시 스키마 및 마이그레이션 문서 동기화

2. 프론트, 백엔드 개발 패턴 통일

공통 원칙

  • 네이밍 규칙 통일: 기능 기준 명명 + 일관된 suffix 사용
  • 계층 책임 분리: 화면/요청 처리/비즈니스/데이터 접근 역할 명확화
  • 에러 처리 표준화: 사용자 메시지, 로그 포맷, 예외 매핑 규칙 통일
  • 테스트 기준 통일: 최소 단위 테스트 + 핵심 플로우 통합 테스트 확보

프론트 패턴

  • API 호출은 services를 통해서만 수행
  • UI 컴포넌트는 표현 로직 중심, 비즈니스 로직은 훅/서비스로 분리
  • 공통 타입을 기준으로 요청/응답 모델 표준화

백엔드 패턴

  • Controller: 입력 검증/응답 포맷
  • Service: 트랜잭션 및 비즈니스 규칙
  • DAO/Mapper: 데이터 조회/저장 책임 한정
  • DB 변경은 SQL + 문서 + 실행 스크립트까지 한 세트로 관리

3. superpowers 스킬을 이용한 AI 개발

왜 쓰는가

  • 작업 접근 방식(브레인스토밍, 디버깅, 계획 수립)을 표준화
  • 코드 변경 전 요구사항 정리와 검증 절차를 강제
  • 팀원 간 AI 활용 편차를 줄이고 산출물 품질을 일정하게 유지

기본 사용 흐름

  1. 작업 요청 수신
  2. 관련 스킬 선택 (brainstorming, writing-plans, verification-before-completion 등)
  3. 설계/계획 문서화
  4. 구현 및 검증
  5. 리뷰 및 반영

실무 적용 팁

  • 단순 수정도 최소한의 설계 의도를 먼저 합의
  • "완료" 선언 전 테스트/검증 로그를 반드시 확인
  • 공통 프롬프트 템플릿과 스킬 사용 예시를 팀 문서로 축적

4. 공통된 작업지시서를 가지고 시연

시연 시나리오 (예시)

  • 주제: "메뉴 관리 기능에 필드 1개 추가 및 목록/상세 반영"
  • 목표: 같은 작업지시서를 바탕으로 프론트/백엔드/DB 변경을 일관되게 수행

작업지시서 템플릿

  • 배경/목적
  • 요구사항 (필수/선택)
  • 영향 범위 (프론트/백엔드/DB)
  • API/데이터 계약 변경 사항
  • 테스트 케이스
  • 완료 조건(Definition of Done)

시연 순서

  1. 작업지시서 확인 및 질의
  2. AI 스킬 기반 계획 수립
  3. 프론트/백엔드 병행 구현
  4. 테스트 실행 및 결과 확인
  5. 리뷰 포인트 정리

마무리

핵심 메시지

  • 구조를 맞추면 협업 속도가 빨라진다.
  • 패턴을 맞추면 유지보수가 쉬워진다.
  • 스킬 기반 AI 활용으로 품질 편차를 줄일 수 있다.
